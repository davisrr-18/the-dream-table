# The Dream Table 1.0.0 Bug Ledger

Findings from the Marco 4 bug-discovery audit (2026-10-28): two read-only `investigator` passes (A: materials and destructive operations; B: authorization, isolation, persistence). High findings were re-traced by the orchestrator. No bugs were reported from play. Resolved findings remain as regression history.

Severity follows `roadmap/v1.0.0-release.md` (Marco 4).

## Resolved in Marco 4

### H1. Take Down without break permission orphans the farm

- Severity: High
- Status: Resolved
- Reproduction: Owner in adventure mode, or the farm inside spawn protection or a claim that denies breaking, presses Take Down.
- Expected: Take Down is refused, or the farm record stays until its blocks are really removed.
- Actual: The finished record (identity, name, grants, invites, alerts) is released first; every block is then skipped silently and the job ends. The farm stays standing, unlisted and unprotected.
- Cause: `FarmCare.takeDown` releases `farm.farm().key()` before any permission check; `FarmDismantler.removeStep` skips blocks where `BuildPermission.canBreak` fails and the job ends without a message when nothing was removed.

### H2. A Take Down in progress is lost after a server restart

- Severity: High
- Status: Resolved
- Reproduction: Start Take Down, log off (the job waits for the owner) or stop the server mid-job, restart.
- Expected: The job resumes.
- Actual: The job ends with `discard_changed`; remaining blocks stay, the farm is gone from My Farms, remaining refunds are lost.
- Cause: The job stores only the `saved:` layout id; that layout is registered in `FarmTemplates.SAVED` only from `FarmAreas` records, and the record was released when the job started.

### H3. A finished session re-records a taken-down farm after reload

- Severity: High
- Status: Resolved
- Reproduction: Build a farm and leave the table session in DONE; Take Down (or Forget) the farm from My Farms; restart or reload the table chunk.
- Expected: The farm stays gone; a Repair-completed alert fires once.
- Actual: The DONE session records the farm again as a new instance (new id, no name/grants), which can then be repaired back. A Repair-completed DONE session repeats its alert on every load.
- Cause: `SessionAreas.finishedRecorded` is not persisted, so `SessionBuild.tick` calls `complete()` again after every load.

### H4. Leftover delivered materials are destroyed when another farm is chosen after DONE

- Severity: High
- Status: Resolved
- Reproduction: Deliver all materials, build or repair over a partly existing farm (skipped steps don't spend), then pick another farm or start Repair on another farm.
- Expected: Unused deposits return to the player.
- Actual: They vanish.
- Cause: `TableSession.setSelectedFarm` calls `desk.reset()` without `returnAll`; `hasProgress()` is false in DONE so `TableButtons.openFarm` and `FarmCare.repair` reach it.

### M1. Take Down removes and refunds every matching block, not only what the farm placed and paid for

- Severity: Medium
- Status: Resolved
- Actual: `FarmCare.takeDown` passes all-set `placed` and `paid` sets. Pre-existing matching blocks skipped during the build are removed and refunded; farms built in Creative refund full materials in Survival.
- Note: matches the "as mining them would" design comment but conflicts with the precise discard path. Fixing needs `placed`/`paid` persisted in finished records (additive save field, all-set for legacy records).

### M2. Take Down area claim is keyed to the farm's original table

- Severity: Medium
- Status: Resolved
- Actual: The job runs on the player's table B but the DISMANTLE claim uses the original table A. Breaking B mid-job drops the job but leaks the claim (blocks new farms there) while the record is already gone; if A is gone, `tableGone` removes the claim while the job runs. `ChunkKeeper.keepTable` keeps A, not B, loaded. Items removed in a batch are lost if `tick` throws before `batch.hand`.

### M3. Heavy C2S requests lack throttling and some skip the open-menu check

- Severity: Medium
- Status: Resolved
- Actual: `CheckPlacementPayload` has no cooldown or menu check and scans all steps; `FarmDetailsPayload` and `LoadedFarmsPayload.Request` have no cooldown; `PlaceFarmPayload` and `DepositMaterialPayload` check distance only; spectators can deposit. Effects stay on the sender's own session, but a modified client can load the server thread.

### M4. One corrupt finished record can empty a dimension's farm records

- Severity: Medium
- Status: Resolved
- Actual: `FarmAreas` read decodes each record with no per-record guard; `TemplateCodec.decode` can throw on malformed arrays. Related Low: `FarmLoader` read does not cap keys per player.

### M5. My Farms send can fail on long saved layout ids

- Severity: Medium
- Status: Resolved
- Actual: `LoadedFarmsPayload` strings are capped at 256 chars; saved ids embed the imported file name (uncapped), so a name of about 193+ chars throws `EncoderException` when My Farms is sent.

### M6. Exception after a block is set leaves a free, untracked block

- Severity: Medium-Low
- Status: Resolved
- Actual: In `FarmBuilder.place`, a throw after `setBlockState` stops the build; on retry the block is skipped as already present, without spending or `recordPlaced`.

### L1. Refused Repair leaves the session changed

- Severity: Low
- Status: Resolved
- Actual: `FarmCare.repair` sets the selected farm, swaps and placement before `beginRepair` can fail with `repair_busy`, overwriting the previous selection and leaving a phantom placement.

### L2. Smaller items

- Severity: Low
- Status: Resolved except the documented placement design limit
- Revoked operator keeps an active Repair (`SessionBuild.tick` checks the lease, not the role).
- Refunds can go to a dead owner on the death screen and are lost on respawn.
- Imported schematics keep container `Items` NBT (admin-controlled input).
- `ObstacleRules.afterReplace` removes the other half of a tall block without `canBreak`.
- `RequestSessionPayload` works at 256 blocks; `ServerSchematicsPayload.Request` serves any id without a table check.
- Placement into replaceable blocks consults `canPlayerModifyAt` only (documented design limit for claim mods).

## Resolution summary

- H1: Take Down refused up front without permission (`mayTakeDown`); a job that cannot break protected blocks restores the record with its original identity and the steps still standing (`restoreRecord`).
- H2: Take Down jobs persist their layout, host table and farm identity (additive NBT); legacy jobs read as before; a corrupt job is skipped and its claim freed.
- H3: `FinishedRecorded` persisted in `BuildProgress`; legacy DONE sessions are recorded only when no record exists and at least half the farm stands.
- H4: `setSelectedFarm` returns leftover deposits to the acting player (or drops them at the table) before resetting.
- M1: finished records persist `placed`/`paid` (legacy = all-set); Repair OR-merges placed and overwrites paid for re-placed steps; Take Down uses them.
- M2: dismantle claim and chunk keeping use the host table; `dropMaterials` releases job claims; batch hand-over in `finally`.
- M3: `RequestThrottle` (10 requests / 20 ticks, toggles exempt); PlaceFarm requires the open menu; spectators rejected.
- M4: per-record guard in `FarmAreas.read`; `FarmLoader` keys capped per player.
- M5: `LoadedFarmsPayload` id strings allow 1024 chars (bytes unchanged up to 256).
- M6: post-placement side effects guarded so a set block is always paid and recorded.
- L1: Repair lease taken before the session changes.
- L2: revoked operator stops Repair; dead owner treated as away (sync flag kept); player schematics stripped of container contents; tall-block other half respects `canBreak`; `ServerSchematicsPayload.Request` left unchanged (client has no retry; see backlog).

Regression coverage: `FinishedFarmsTest`, `FarmAreaKeyTest`, `BuildProgressTest`, `MaterialLedgerTest`, `LegacyDoneTest`, `RequestThrottleTest`, `FarmLoaderReadTest`, `PayloadCodecsTest`, `SchematicValidationTest`. `./gradlew build`: 257 tests, 0 failures.

## Backlog (Low)

- `ServerSchematicsPayload.Request` unbounded (needs a client retry or per-player budget).
- `TemplateCodec.decode` skips unknown entity types, shifting persisted step indices (only after removing a mod).
- A corrupt `FarmAreas` record is dropped permanently (raw NBT not kept for recovery).
- `blockEntity.read` failure after placement is only logged.
- Placement into replaceable blocks consults `canPlayerModifyAt` only (design limit).
