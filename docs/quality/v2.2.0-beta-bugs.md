# The Dream Table 2.2.0-beta Bug Ledger

Known findings in flows changed for 2.2 are recorded here through release validation. Resolved findings remain as regression history.

## Resolved

### Repair can leave a minecart passenger unmounted

- Severity: Medium
- Status: Resolved
- Reproduction: Damage an iron farm so only its zombie passenger or only its empty vanilla minecart remains, then start Repair. A failed entity spawn or mount also reproduces an orphaned partial pair.
- Expected: Repair reuses exactly one free matching passenger or one empty vanilla minecart in that cell, creates only the missing component, and rolls back only entities created by the failed attempt.
- Actual: Repair treated any matching passenger as complete. When spawning a pair, it ignored a failed mount and could leave newly spawned entities behind after a partial failure.
- Cause: Entity presence was checked independently of the required passenger/cart relationship, and the spawn path did not model partial states or verify `startRiding`.
- Regression coverage: `MinecartPairingTest` covers the complete partial-state matrix, exact cell filtering, ambiguous candidates, and mount-failure rollback; `BuildIssueTest` covers the persisted non-temporary entity blockage.
- Resolution: Exact local counts now choose one explicit pairing action. Occupied or ambiguous cells stop with `ENTITY_BLOCKED`; spawn and mount failures discard only entities created by that call.
