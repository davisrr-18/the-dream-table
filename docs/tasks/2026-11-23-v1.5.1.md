- F3 (Medium, read only; needs a corrupt or edited save): a saved repair whose `RepairContext` cannot be read (`RepairFarmKey` malformed, or an owner/actor UUID missing) loads with `repair()` true and no context (`BuildProgress.java:350-354`, `RepairContext.java:26-35`). `SessionBuild.endRepairIfInvalid` then skips the lease and permission checks, and `FarmAreas.reconcileRepairs` drops the lease, so a second player can start a repair on the same farm and the placed steps are never merged into the record. Test idea: `BuildProgress.read` with `Repair=true` and a bad key.
- F4 (Low, confirmed in `SessionBuild.java:40-41,327-331`): the per-step failure counter is memory only, so after a reload the "repeated, look at the spot" message never appears (stays "try again"). Fix idea: seed from the saved `BuildIssue.attempts`.
- F5 (Low, needs corrupt data): a malformed `MovedBuildDimension` reads as null (`TableSession.java:919-921`), so a parked project loses its area reservation and the world guard on resume.
- F2 (Low, accepted in v1.5.0): table replaced with flag 256 on 1.21.11 has an untested path.
