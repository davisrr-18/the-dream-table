## Decisions that were open at the end of Milestone 1 (resolved, see above)

1. **Slot delivery does not resume a build.** `finishDelivery` (`TableSession.java:533`) runs only after hand delivery (`offerFromHand`) and the bulk buttons (`finishBulk`); `MaterialDesk.absorbSlots` does not call it. With the clipboard gone, slot delivery is the manual path, so a build waiting in `PHASE_NEED` would need Build pressed again, while `issue.material.fix` promises it continues alone. Recommended: make slot delivery resume the build too (small server change). Alternative: reword the text.
2. **`DepositMaterialPayload`** (only sender is the clipboard). Recommended: remove sender, receiver, `offerFromHand` and the payload, and bump `NetworkProtocol.VERSION` 3 to 4 (1.3.0 clients cannot join a 1.4.0 server; the mod is required on both sides anyway). Alternative: delete only the sender and keep the unused server path, protocol stays 3.
3. **1.20.1 branch:** ship 1.4.0 there too (cherry-pick, own milestone)?

## In-game test of the Requirements page, round 1 (2026-11-11, user with screenshots)

The user ran a 1.4.0 build and reported: (1) the page looked broken and out of proportion, it should expand with the GUI size to the panel edge (the cards' count texts overlapped each other; the content sat in a 196 px strip on the left of a 384 px panel); (2) items dragged into the Requirements slots were not counted.

- (1) Cause: the page reused the 1.0.0 slot grid (9 columns of 18 px with count text under each slot, fixed 196 px slot region), never exercised before 1.4.0. Fix: `RequirementsLayout` (new) lays the page out as one card per material with the real slot on the card icon, 1 column on compact and 2 on wide, inventory centered, then Deliver All, Deliver From Nearby and Back; the slot region of a slot page is now the whole panel width (`ScreenGeometry`); `DreamTableScreenHandler.alignSlots` replaces the client-side slots when the column or material count changes (replaces `alignInventory`).
- (2) Cause (read from code, not reproduced): `TableSession` passed `table::markDirty` as the desk's change callback, which does not mark the session for the client; only `sync()` does, and only the delivery buttons called it. A slot deposit reached the server ledger, but the client kept the old counts. Fix: the callback is `this::sync`. Not covered by a unit test (needs a block entity in a world).
- Tests: `DreamTableLayoutTest` now covers columns 1 and 2 and 0 to 54 materials; `ScreenGeometryTest` expects the full-width slot region on wide.
- Not seen in game yet after the fix: layout in compact and wide, drag and drop counts, shift-click, scrolling with slots partly out of view.
