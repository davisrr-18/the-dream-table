## Milestone 1 results (2026-11-04)

Agents actually run: 4 `investigator` (Haiku 5.5 high), read-only: moved-table bug, persistence bug hunt, build/repair/network bug hunt, water sizing. Findings are from code reading; none run in game, none yet re-verified by the orchestrator.

**Known bug (moved table):** by design since 1.1.1 ("placement re-done at the new table"). The aimed spot lives only on the client until Build (`PlaceFarmPayload`); breaking the table clears it (`DreamTableHologram.settle(GONE)`), so `TableSession.park` has nothing to keep. After Build the anchor is parked and restored paused (code path only, unconfirmed in game). Fix if wanted: new `TableSession` field for the unconfirmed spot, written in `park`, sent in `writeForClient`, drawn when IDLE, revalidated (`problemAt`, `withinReach`) on restore; `ParkRulesTest` lines 35-38 change on purpose. Needs user decision (reverses a recorded decision).

**Bug candidates (ranked):**
1. MED: parked BUILD project releases its area claim (`TableSession.java:599`), so another build's layer clear (`LayerClearer` `removeWithoutDrops`) can erase its paid blocks, no refund.
2. MED: breaking the table during a Discard take-apart loses refunds of steps not yet removed (`DreamTableBlockEntity.java:286-292`, `FarmDismantler.java:178-181`).
3. LOW-MED: refused Repair mutates selection/placement first (`FarmCare.java:57-62`, `SessionBuild.java:228-233`); contradicts its own comment; session stuck on repaired farm. Found by two investigators.
4. MED (old worlds only): legacy shared session adopted by whichever player calls the server first, even without opening the table (`DreamTableBlockEntity.java:167-179`, `CheckPlacementPayload.java:71`).
5. LOW-MED: unreadable finished-farm record does not reserve its area (`FarmAreas.java:676-690`).
6. LOW: session entry without Player UUID dropped on next save (`DreamTableBlockEntity.java:401-407`).
7. LOW/optional: `BUTTON_BUILD` without anchor (modified client only); `FarmProtection.structuralAt` O(steps) per break.
Not verified: pistons moving the table; LayerClearer internals, PendingRefunds only partly covered.

**Water (option A sizing):** M, about 6 Java files + lang + tests, medium risk. Keep `WATER_BUCKET` on steps (changing it changes `FarmTemplate.signature()` and breaks running builds, Take Down, saved layout ids). Exclude water from materials in `FarmTemplate.of`; `FarmBuilder` water step needs a nearby infinite source (6-block radius, source with 2+ horizontal source neighbours, loaded chunks, excluding water inside Dream Table farm areas), no spend, no bucket return; new `NearbyWater`, `BuildIssue.WATER`, clipboard row computed client-side (no protocol change); old saves with delivered buckets get refunded by `reconcileMaterials`. Option B is S-M and needs a per-farm flag plus presence/alerts/hologram handling. Not verified: Yarn FluidState names, which version added `DeliveredItems`.
