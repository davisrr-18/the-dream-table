# Task: v1.1.1 — keep each player's project when a Dream Table is broken

- Status: In progress (Milestone 1 done, awaiting approval for Milestone 2)

## Objective

Breaking a table (by anyone, any means) must not lose a player's project. Each player's session is parked per player in
world saved data and comes back into the next Dream Table that player opens. 1.1.1 also ships the Stop/Resume Placing key
(commit e2a5994 era, already on main).

## User decisions (2026-10-31)

- Storage: per player, in world saved data (not in the dropped item). Each player recovers only their own project.
- Delivered materials: kept in the parked project, no longer dropped.
- Started build: continues at the same spot from the new table when within reach; moving it needs Take Down first.

## Acceptance criteria

- [ ] Breaking a table parks every non-empty session (farm, placement, materials, progress, page) instead of dropping materials.
- [ ] Explosions, pistons, commands and operators park too (hook: `DreamTableBlock.onStateReplaced` -> `dropMaterials`).
- [ ] Opening any table restores the player's parked project when that table holds no project of theirs; never overwrites.
- [ ] A started build is restored paused; resuming works when the new table is within 48 blocks (FarmGeometry.AIM_RANGE) of the anchor, same dimension, and the footprint is free; otherwise it stays paused with a clear notice and remains in the table (Discard still available).
- [ ] Old (1.1.0) worlds and tables load unchanged; unreadable parked entries are kept as saved.
- [ ] Round-trip and restore-rule tests; `./gradlew build` green; server smokes by the user.

## Scope

- In: new `ParkedProjects` PersistentState (overworld, per-player list, frozen key added to PersistentStateKeysTest); park in
  `DreamTableBlockEntity.dropMaterials`; restore in the server branch of `session(UUID)`; re-claim BUILD area under the new
  table key on resume (conflict check, `inRange` moved out of `network`); reset SessionBuild caches on restore; notices
  (en_us + pt_br); TableBreakGuard: the owner may break their own table with a build (it is parked now); CHANGELOG 1.1.1.
- Out: Take Down (FarmDismantler) jobs keep today's behaviour (record restored, claim released). Moving a started build to a new spot.

## Technical decisions (from investigation)

- Session NBT holds no table pos; anchor is absolute -> park `TableSession.write` output plus dimension.
- Anchor-less sessions (farm chosen, not placed) park farm + materials only; placement re-done at the new table.
- A running repair is ended on park like `cancelRepair` (its RepairLease stores the old table pos).
- BUILD claim is already released by `FarmAreas.releaseTable` on break; a paused parked footprint is unclaimed until resumed; resume re-checks conflicts (`SessionAreas.problemAt`, `insideOtherFarm` uses the new key).
- Guard: BUILD no longer stops the owner; other players stay blocked (anti-grief, unchanged); UNREADABLE and TAKE_DOWN unchanged.
- Restore server-only; client keeps `receiveOwnSession`. Several parked projects per player kept as a list, restored oldest first, capped like PendingRefunds.
