## Objective

1. **In-game feedback form** on the Settings tab (Options page). The text goes to a Cloudflare Worker, which writes each submission into the user's vault (Rede Neural), in a new **feedback** area inside the The Dream Table project. Only technical data is sent: text, category (bug, idea, other), mod version, loader, Minecraft version. Nothing that identifies the player.
2. **How It Works on My Schematics**: help text on where to save schematic files, which formats and size are read, how schematics work on a server, and why a file shows greyed out.
3. **Audit fixes (2026-11-06, confirmed by reading)**: ChunkKeeper skips the ticket of the first loaded chunk; the placement preview erases a finished farm's record; discarding a build without a farm neither dismantles nor warns; scheme button IDs collide with material swaps above 800 schemes. Each one is reproduced by a test before the fix.
4. **Page 21 hypothesis**: `TableSession.REMOVED_ALERTS_PAGE` and `DreamTableScreenHandler.PAGE_FARM_INFO` are both 21. Confirm by test, then fix.
5. **Minecraft 1.21.11 port** on a new branch `mc/1.21.11`, carrying 1.5.0, as its own final milestone.

Items 1 to 4 also go to `mc/1.20.1` by cherry-pick, as in 1.4.0.

## Milestone 1 findings

- **ChunkKeeper** (`farm/ChunkKeeper.java:44-45`): default `Long.MIN_VALUE` makes `now - last` overflow negative, so the first `keepSpot` of an already loaded chunk returns without a ticket. Fix: default `now - RENEW_TICKS`. Memory only, no NBT.
- **Preview erases finished farm** (`farm/FarmAreas.java:402-406` in `conflict`, reached from `CheckPlacementPayload` via `SessionAreas`). `forgotten` (`:551-557`) removes a finished farm without layout or under 50% loaded. Fix: `conflict` skips it without removing; `find` uses the same rule.
- **Discard without farm** (`block/entity/TableSession.java:665`): `template != null` gate has no else; reset at `:690-698` runs anyway. Fix: send `discard_changed` when `takeApart` and the template is gone.
- **Button IDs** (`screen/TableButtons.java:80-86`; `SchemesPage.java:67`; `ServerSchematicsPayload.java:35`, cap 1024). Fix: cap at `BUTTON_SWAP_OPEN - BUTTON_SCHEME` (800) with a notice; protocol 4 to 5.
- **Page 21** (`TableSession.java:51-52`, `:885-891`; `DreamTableScreenHandler.java:44`): Farm Info is persisted as 21 and read back as the removed Alerts page, so it reopens on My Farms. Fix: `write()` saves `PAGE_WORK` for Farm Info through a static `savedPage(int)`; ids unchanged. Residue: sessions saved on 21 before the fix reopen on My Farms once.
- **Schematics help**: a small new page (id 22, button 112) that reuses `FarmInfoText.layout`; facts from `ImportedStructures.java:77-119`, `SchematicReader.java:34-44`, `ImportNote.java:26-50`. The code also reads `config/litematica` and `config/the_dream_table/structures`, and reads the world folder before the latter; the README must match the code.
- **Feedback form**: only `SearchBox` uses a `TextFieldWidget`. `DreamTableScreen.keyPressed` (`:267-313`) runs R/M hologram keys before any focus check and ESC closes Options; the feedback field needs the search gate (`:268-270`). No HTTP or client executor exists; Java 21 `HttpClient` with `sendAsync`, result back on the client thread, shown with `TableNotices`. Version: Fabric has it (`FabricHandshake.java:120-124`), NeoForge/Forge need a per-loader accessor. Lang keys go into `en_us.json` and `pt_br.json` (`LangParityTest`).

## Milestone 3 findings (1.21.11 port, 2026-11-20)

Method: `git archive` of 40af0c5 into the scratchpad, versions bumped, `:common:compileJava` with `-Xmaxerrs 5000`, `genSources` unpacked (Minecraft and Fabric API 1.21.11, Yarn names), three read-only investigators by subsystem. Nothing changed in the repository.

- **Toolchain (checked on the mavens):** Minecraft 1.21.11 (Java 21), Yarn `1.21.11+build.6`, Fabric API `0.141.6+1.21.11`, Fabric Loader 0.20.1, NeoForge `21.11.48`, Forge `1.21.11-61.2.5`. Loom 1.17.493, architectury-plugin 3.5.170 and Gradle 9.4.1 stay (already the newest). The NeoForge Yarn patch only exists up to `1.21+build.6`; NeoForge configures with it.
- **Forge blocker, solved in the scratch build:** Forge fails "Failed to remap minecraft" because Yarn names `BucketItem.method_74140` `getFluid` and Forge adds its own `getFluid()`. Same without the NeoForge patch. A one-line tiny v2 layer only for the forge module (`method_74140` -> `getVanillaFluid`) makes it configure (BUILD SUCCESSFUL). Vault: experience note of 2026-11-20.
- **Size:** about 490 distinct errors in 69 `common` files on the first javac pass (farm ~250, client ~110, block ~100, network ~30, screen ~30). More appear after these resolve, as on 1.20.1. Loader modules and the 126 test files not compiled yet (they need `common`).
- **Persistence (high risk, save compatibility):**
  - NBT getters return `Optional`; `contains(key, type)`, `putUuid/getUuid` and `toNbtList` are gone; ~230 lines in 22+ files, no central helper. UUIDs: `get/put(key, Uuids.INT_STREAM_CODEC)` reads the 1.21.1 `NbtIntArray` (checked by `javap`). Never `Uuids.CODEC` (string).
  - `PersistentState` becomes `PersistentStateType(id, ctor, codec, DataFixTypes)`. The five states (FarmAreas, ParkedProjects, PendingRefunds, FarmPreferences, FarmLoader) keep their ids and the `data` root (1.21.1 saves under `data`, checked). **A null `DataFixTypes` throws inside `readNbt`, the exception is swallowed, the state loads empty and the next save wipes the world's farms.** Use a non-null type without fixers (e.g. `SAVED_DATA_COMMAND_STORAGE`); a regression test must read a 1.21.1-format fixture.
  - BlockEntity `readNbt/writeNbt` -> `readData(ReadView)/writeData(WriteView)`; `FarmBuilder.settlePlaced` needs `NbtReadView.create`. Views report and skip bad entries instead of throwing: `GuardedRead`'s "malformed entry throws" contract (architecture.mdc, never silently dropped) needs `orElseThrow` on required keys.
  - Long arrays have no view method (keep `NbtLongArray`, never a list codec). Inventory format unchanged (no slot index in 1.21.1 either, checked).
  - Bundled and player schematics: the readers need no fixer, but renamed ids are not migrated; add a test that every bundled palette and entity id resolves on 1.21.11.
- **Gameplay:** the block entity is removed before `onStateReplaced` (`WorldChunk`), so `table.onBroken` must move to `BlockEntity.onBlockReplaced` or breaking a table returns and protects nothing. `ChunkTicketType` is a registered record (needs `Registries.TICKET_TYPE` through `Platform.content()`). Block and item settings need `registryKey` (NPE at startup otherwise); item name needs `useBlockPrefixedTranslationKey()`. Permissions: `hasPermissionLevel(2)` -> `CommandManager.requirePermissionLevel(... GAMEMASTERS)`. `GameRules` moved to `world.rule` with `getValue`. `TypedActionResult` -> `ActionResult` in the `UseItemListener` seam. `getWorld/getServerWorld` -> `getEntityWorld`.
- **Resources:** recipe ingredients become plain strings; new `assets/the_dream_table/items/dream_table.json`; Forge `pack.mcmeta` 75 (`supported_formats` [75, 94]); version ranges in the three mod metadata files.
- **Client (largest rewrite):** `RenderSystem` state, `BufferRenderer`, `VertexBuffer`, shader programs and `renderFilledBox` are gone: `GhostRenderer` (487 lines) is a rewrite onto custom `RenderPipeline`s (solid, translucent, no-depth, textured) with per-draw tint through `DynamicTransforms`; its pure geometry (PlacementOutline strips, FrameBudget, WeightedCache, GhostPlan) stays; keep own strips, not the LINES pipeline. Fabric `AFTER_TRANSLUCENT` and `BLOCK_OUTLINE` are gone (`END_MAIN`, `BEFORE_BLOCK_OUTLINE`), which changes draw order against translucent terrain. `FarmMiniature` moves to the render-state BER API (the `isRemoved()` guard goes into the state). `FarmFaces` moves from `BakedModel` to `BlockStateModel`/`BlockModelPart`. HUD to `HudElementRegistry`. GUI matrices become 2D `Matrix3x2fStack`. Input moves to `KeyInput`/`Click`/`CharInput` records and `KeyBinding.Category`. `EditBoxWidget` can no longer be subclassed (package-private constructor): the FeedbackForm click gating moves to the screen. `GameRenderer.setRenderHand` is gone and `renderHand` is private (map mode hand: decision below).
- **Loaders:** Fabric API calls all exist except the moved world-render package and `UseItemCallback` returning `ActionResult`. NeoForge 21.11 and Forge 61 APIs are unverified until they compile (Forge networking and `TickEvent` are the main risks).
