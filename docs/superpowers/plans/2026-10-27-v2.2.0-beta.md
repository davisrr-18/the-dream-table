# The Dream Table 2.2.0-beta Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the approved stabilization pass, adaptive menu redesign, and secure cooperative farm operations as The Dream Table 2.2.0-beta.

**Architecture:** Keep physical finished-farm records and new farm-owned metadata in each dimension's `FarmAreas`, address them through immutable `FarmKey` UUIDs resolved by a stateless server-side `FarmDirectory`, and keep per-player preferences in one overworld state. Refactor the client menu around pure geometry/routes plus registered focusable controls, while retaining fixed handled-slot coordinates and all existing persisted page ids. Build cooperative Repair around a persisted owner/actor lease and derive every capability on the server.

**Tech Stack:** Java 21, Minecraft 1.21.1, Fabric Loader/API, Yarn 1.21.1+build.3, JUnit 5 with fabric-loader-junit, Gradle 8.14.3.

**Spec:** `docs/superpowers/specs/2026-10-27-v2.2.0-beta-design.md`

## Global Constraints

- Preserve existing NBT keys and page ids; all additions are optional and use safe legacy defaults.
- The server derives actor UUID from the authenticated player and resolves owner/role from the current `FarmRecord`; clients never supply trusted owner, role, or list index.
- Compact layout is 196 logical pixels below 420 scaled pixels; wide layout is 384 pixels at 420 or wider.
- Handled slots keep their fixed `Slot.x/y`; drawing, highlight, tooltip, and hit testing share one calculated slot origin.
- Farms use immutable public keys `dimension|instanceId`; internal positional `FarmAreas.Key` never crosses the network.
- Owner-only actions are Rename, Share, Take Down, and Forget. Operators add Repair and Keep Loaded to Viewer capabilities.
- Sharing defaults to enabled, eight collaborators per farm, 32 incoming invites per player, and seven real days per invite.
- Names are trimmed, non-unique, at most 32 Unicode code points, reject controls and `§`, and empty restores the default.
- Keep Loaded data and quota belong to the Owner; lowering limits never deletes persisted selections.
- No remote item transport, ownership transfer, public farms, cross-server identity, or automatic repair.
- Player-facing copy, code comments, README, and changelog remain English.
- Every behavior change follows RED→GREEN and runs `./gradlew compileJava`; logical changes also run `./gradlew test`.

## Review Focus

- A legacy world containing positional Keep Loaded keys, missing instance UUIDs, and a duplicate manipulated UUID migrates once without losing or cross-linking farms; covered in Task 4.
- A player changes tabs or resizes while carrying a cursor stack and while material slots are partially clipped; no slot outside the viewport can be activated and no item is lost or duplicated; covered in Tasks 2 and 3.
- An Operator begins Repair, is revoked, the server restarts, and the operation resumes/completes under the original Owner; covered in Task 7.
- A Viewer forges alert acknowledgements or action payloads for an inaccessible farm; nothing is disclosed or mutated; covered in Tasks 6 and 8.
- A pending invite expires or reaches a now-lower limit between display and acceptance; acceptance fails explicitly without deleting the invite or existing grants; covered in Task 5.
